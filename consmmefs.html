The Challenge

Designing for an
entire ecosystem.

The existing experience was fragmented and difficult to navigate. Prospective students struggled through the admission process, while enrolled students had to complete important academic tasks through interfaces that weren't designed around their needs. Administrators also needed a system capable of managing thousands of records without sacrificing efficiency.

The challenge wasn't simply improving individual screens — it was designing a complete ecosystem that could support different user groups while maintaining a consistent experience throughout the student's lifecycle.

The Core Insight

Every user group needed something different, but they all needed it to feel like one system.

Design Process

Mapping the full
student lifecycle.

Rather than redesigning screens in isolation, I worked through the system end to end — from how applicants and administrators actually used the existing portal, to how a rebuilt version could support every stage of the student journey consistently.

01
Understand Existing Workflows

Looked at how students and administrators were actually moving through the current portal, day to day.

02
Audit the Current Portal

Went through every existing screen and flow to identify gaps, inconsistencies, and points of friction.

03
Map Student & Administrator Journeys

Charted the full path each user group takes, from admission through to graduation and day-to-day administration.

04
Design Improved User Flows

Rebuilt the flows around clarity and consistency, rather than around how the old system happened to be structured.

05
Create Wireframes

Sketched low-fidelity layouts for each key screen to test structure and hierarchy before moving to visual design.

06
Build a Consistent UI System

Established shared components and patterns that would hold up across every module of the portal.

07
Prototype Key Interactions

Brought the most important flows to life to test how they would actually feel to use.

08
Iterate Based on Stakeholder Feedback

Refined the designs against feedback from the school to make sure the system matched real operational needs.

Design Goals

Objectives that guided
every decision.

Rather than chasing a single before-and-after transformation, I worked from a set of objectives that shaped the platform across every user group and module.

Design Objectives

Simplify admissions for first-time applicants

Create a consistent experience across every student touchpoint

Reduce administrative workload through better workflows

Make important academic information easier to access

Build a scalable foundation for future modules

Key Screens

Built around what
each user needs.

Gives students a single home base for academics, payments, and records — replacing a set of disconnected tools with one consistent experience.

Brings course registration, results, transcripts, and timetables together, so important academic information is never more than a click away.

Gives administrators a structured, role-based way to manage admissions and student records at scale, without the workload growing with every new student.

Outcome

A cohesive digital
ecosystem.

The redesign transformed the portal into a cohesive digital ecosystem that supports users throughout their academic journey — from submitting an admission application to managing academic records after enrollment. By creating consistent navigation, clearer information hierarchy, and streamlined workflows, the new experience reduces friction for students while giving administrators better tools to manage admissions and student operations efficiently.

Design Philosophy

A campus runs on more than admissions — the system supporting it should feel like one place, not a dozen disconnected tools.
